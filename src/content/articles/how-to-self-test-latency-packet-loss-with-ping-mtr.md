判断一个机场代理节点连接质量好不好，光看客户端界面上的"延迟测试"按钮往往不够全面。用系统自带的 Ping 命令和更专业的 MTR 工具，可以自己动手测出更完整的延迟和丢包数据。这篇文章说明具体怎么操作，测速的整体思路可以先看 [机场测速怎么做](/tutorials/how-to-test-airport-speed/)。

## 直接结论

- Ping 命令几乎所有系统都自带，适合快速查看某个目标的延迟和丢包率，操作门槛最低；
- MTR（或 Windows 下的 WinMTR、pathping）能显示完整的逐跳路径，适合定位延迟或丢包具体出现在哪一跳；
- 单次测试结果只能反映当时的网络状况，判断节点是否真正稳定，需要多测几次、覆盖不同时段。

## 用 Ping 测延迟和丢包率

Ping 的原理是向目标地址发送数据包，并记录对方响应所用的时间，多次发送后可以统计出丢包率。

**Windows**：打开命令提示符（CMD），输入 `ping 目标地址 -n 20`，回车后会连续发送 20 次请求，结束后会显示丢失的数据包数量和百分比，以及最短、最长、平均延迟。

**macOS / Linux**：打开终端，输入 `ping -c 20 目标地址`，效果和 Windows 下的用法基本一致。

这里的"目标地址"可以是节点的落地 IP，也可以是常见的公共服务器地址（用于测试你本地网络到某个方向的基础质量）；具体测哪个地址，取决于你想验证的是"到节点"还是"到某个服务"的网络状况。

一次典型的命令回显大致是这样的结构（以下为示例格式，不代表任何真实测试数据）：

```
已发送 = 20，已接收 = 20，丢失 = 0 (0% 丢失)
往返行程的估计时间(以毫秒为单位)：
    最短 = 35ms，最长 = 48ms，平均 = 40ms
```

看到这类输出后，重点关注两个数字：丢失的百分比，以及平均延迟。这两个数字具体应该落在什么区间才算正常，可以参考 [机场延迟多少算正常](/knowledge/airport-latency-normal-range/) 和 [机场丢包率多少算高](/knowledge/airport-packet-loss-explained/)。

## 用 MTR 定位问题出在哪一跳

Ping 只能告诉你"最终结果好不好"，但没法告诉你延迟或丢包具体发生在链路的哪个环节。MTR（My Traceroute）把 Traceroute 的逐跳路径和 Ping 的持续统计结合在一起，可以看到数据包途经的每一跳节点各自的延迟和丢包情况。

**macOS / Linux**：大多数发行版可以直接安装 `mtr` 工具，安装后在终端输入 `mtr 目标地址` 即可开始持续测试，界面会实时刷新每一跳的数据，按 `q` 退出。

**Windows**：可以使用 WinMTR 这类图形化工具，填入目标地址后点击开始，效果和命令行版的 mtr 类似；也可以用系统自带的 `pathping 目标地址` 命令，只是运行时间会更长一些。

MTR 的每一行代表路径上的一跳，主要看这几列：

- **Loss%**：这一跳的丢包率，如果丢包只出现在中间某一跳，但最后一跳（也就是目标本身）丢包率正常，通常不用太担心，这是路由设备本身对 Ping 请求的处理方式导致的常见现象；
- **Avg**：这一跳的平均延迟，可以看出延迟是从哪一跳开始明显上升的；
- **StDev**（标准差）：数值越大，说明这一跳的延迟波动越大，链路可能不够稳定。

**怎么判断问题出在哪**：如果丢包或高延迟从某一跳开始，并且一直持续到最后一跳，通常说明问题出现在这一跳之后的链路上；如果只是中间某一跳单独异常，而最后一跳（真正的目标）表现正常，大概率是中间设备限制了对探测包的响应优先级，不代表实际业务流量也会受影响。

## 测试时需要注意的几个细节

- **多测几次，不要只看一次结果**：单次测试很容易受到瞬时网络波动影响，为什么每天测速结果会不一样，可以看 [机场测速结果为什么每天不一样](/knowledge/why-speed-test-varies-daily/)；
- **区分"到节点"和"到目标服务"两段路径**：机场代理的实际体验，是"本地到节点"和"节点到目标服务"两段网络质量共同决定的，Ping 落地 IP 只能反映第一段；
- **避免在测试期间进行大流量下载或视频播放**：这类活动会占用带宽，干扰延迟和丢包的测试结果；
- **图形化对照工具**：如果不想用命令行，也可以使用本站提供的 [延迟丢包计算器](/tools/latency-loss/) 辅助理解延迟和丢包对实际体验的影响程度。

拿到测试数据之后，怎么理解这些数字才有参考价值，而不是简单地"好"或"不好"，可以进一步看 [机场测试数据怎么看](/knowledge/airport-test-data-explained/)。

使用任何网络代理服务时，请遵守你所在地区的法律法规。

## 常见问题

**Ping 显示 0% 丢包，是不是说明这个节点很稳定？**
不能这么直接下结论。单次测试的 0% 丢包只代表这一次测试期间没有出现丢包，长期是否稳定需要多次、跨时段的观察，具体可以参考 [机场稳定性怎么比](/knowledge/airport-stability-comparison/)。

**MTR 里中间某一跳显示 100% 丢包，是不是链路坏了？**
不一定。很多路由设备出于安全或负载考虑，会限制或不响应用于探测的数据包，导致中间跳看起来丢包很高，但只要最后一跳（目标本身）表现正常，通常不影响实际使用。

**Windows 上一定要装第三方工具才能用 MTR 吗？**
不一定，系统自带的 `pathping` 命令可以实现类似的逐跳诊断效果，只是运行时间比 WinMTR 更长；如果需要更直观的界面，也可以安装 WinMTR 这类免费的图形化工具。

**测出来延迟或丢包偏高，应该先怀疑哪里？**
可以先怀疑本地网络环境（比如 Wi-Fi 信号、路由器负载），再怀疑客户端和节点选择，具体排查顺序可以参考 [机场连接不上怎么办](/troubleshooting/connection-troubleshooting-step-by-step/) 中关于分层排查的思路。
