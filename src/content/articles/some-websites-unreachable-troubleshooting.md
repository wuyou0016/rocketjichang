这篇文章针对的症状是：客户端显示节点已经连接成功，也能正常打开大部分网站，但个别网站打不开或者打开很慢。这和完全连不上代理是两类不同的问题——如果你遇到的是客户端根本连不上节点，建议先看[机场连接不上怎么办？从订阅、节点到客户端逐步排查](/troubleshooting/connection-troubleshooting-step-by-step/)。这篇文章聚焦"连接本身正常，但部分网站访问异常"这一类具体症状。

## 直接结论：先确认是不是分流规则的问题

大多数客户端（比如 Clash 系客户端）默认使用的是"规则模式"，而不是"全局模式"——规则模式会根据预设的[分流规则](/glossary/rule-set/)判断每一个请求该走代理节点还是直接连接，而不是所有流量都强制走代理。如果某个网站被规则集归类到了"直连"分组，客户端会尝试直接连接这个网站，不经过代理节点。这种情况下如果你的本地网络本身无法直接访问这个网站，就会表现为"代理已连接，但这个网站打不开"，而其他被正确归类为"走代理"的网站可以正常访问。这是目前最常见的一类原因，建议第一步优先排除它。

## 怎么快速验证是不是规则分类问题

1. 打开客户端的模式设置，找到"规则模式""全局模式""直连模式"这几个选项（不同客户端的叫法可能略有差异）；
2. 临时切换到"全局模式"，让所有流量都强制走代理节点，不再经过分流规则判断；
3. 再次尝试打开刚才打不开的网站：
   - 如果切换到全局模式后网站可以正常打开，基本可以确认原因就是分流规则把这个网站分到了直连组；
   - 如果切换到全局模式后依然打不开，说明问题不在分流规则，需要继续往下排查节点或目标网站本身的问题。
4. 确认原因后，记得把模式切换回去——长期使用全局模式会让所有流量（包括访问境内网站）都经过代理节点，可能增加不必要的流量消耗和延迟。

## 规则集没有覆盖到这个网站

分流规则通常依赖规则集来判断域名应该归到哪一类，规则集本身是一份不断维护更新的名单。如果你访问的是比较新、比较小众的网站，规则集里可能还没有收录这个域名，导致客户端按默认策略处理（不同客户端的默认策略不完全一样，有的默认直连，有的默认走代理）。遇到这种情况，一般有两种思路：

- 更新客户端使用的规则集到最新版本，新规则集通常会持续补充新出现的域名；
- 如果客户端支持自定义规则，手动给这个域名添加一条规则，指定它走代理节点。

## 目标网站本身的访问策略，不一定是机场的问题

有些网站会对来自数据中心、云服务商批量分配的 IP 段采取更严格的验证甚至直接拒绝访问，这类 IP 通常称为 [IDC IP（数据中心 IP）](/glossary/datacenter-ip/)。机场节点的服务器大多部署在数据中心，如果你用的这个节点落地 IP 恰好被目标网站判定为高风险 IP，就可能出现"这个节点打不开这个网站，换个节点就正常"的情况。这种情况下，换一个节点或者换一条线路通常比反复排查客户端配置更有效。

## DNS 解析异常导致的部分网站打不开

还有一类情况是 DNS 解析本身出了问题——比如解析到了错误或者过时的 IP 地址，导致网站打不开或者打开的内容不对。这类问题的具体表现和排查思路，可以参考 [DNS 污染和 DNS 泄漏对机场代理用户有什么实际影响](/knowledge/dns-pollution-leak-impact-explained/)，里面详细说明了怎么大致判断是不是 DNS 层面的问题。

## 排查清单

遇到"连上但部分网站打不开"，建议按下面的顺序逐一排除：

1. 切换到全局模式测试，判断是不是分流规则把这个网站分到了直连组；
2. 如果确认是规则问题，检查并更新规则集，或者手动添加自定义规则；
3. 换一个节点或者换一条线路，排除是不是目标网站对当前落地 IP 有限制；
4. 换一个协议（比如从 Shadowsocks 换成 VLESS 或 Trojan）测试，排除协议层面被针对性干扰的可能；
5. 排查 DNS 解析是否正常，必要时手动指定一个公共 DNS 服务器测试；
6. 以上都排除后，也要考虑是不是网站自身在你所在地区就有访问限制，而不是机场代理这一端的问题。

## 常见问题

**为什么大部分网站都能打开，就一两个网站打不开？**
最常见的原因是分流规则把这个网站的域名归类成了直连，而你的本地网络本身访问不了这个网站。可以先切换到全局模式验证，如果全局模式下能打开，基本可以确认是规则分类的问题。

**切换到全局模式后所有网站都正常了，是不是说明我的规则集有问题？**
可以这么理解。建议更新规则集到最新版本，或者针对这个具体网站手动添加一条自定义规则，而不是长期使用全局模式。

**换了节点之后这个网站就能打开了，是什么原因？**
比较可能的原因是原来那个节点的落地 IP 被目标网站判定为数据中心 IP 或者高风险 IP，而换的新节点落地 IP 没有被同样限制。这属于目标网站自身的访问策略，不完全是机场代理的问题。

**全局模式和规则模式应该怎么选？**
日常使用建议优先用规则模式，境内网站可以直连，速度更快、也更省流量；只有在排查问题或者确实需要所有流量都走代理时，才临时切换到全局模式。

**是不是只要用了机场代理就不会再遇到网站打不开的情况？**
不是。机场代理解决的是网络连接层面的问题，个别网站打不开可能涉及规则分类、DNS、目标网站自身策略等多种原因，不能简单地认为用了代理就一定能打开所有网站。
