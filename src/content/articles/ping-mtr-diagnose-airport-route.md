结论先说：遇到延迟高、丢包多的问题，光靠测速软件的一个总数字，很难判断问题出在本机、节点，还是更远的某一段网络；而 ping 和 MTR 这两个免费工具，可以把"到目标的整条路径"拆成一跳一跳来看，帮你大致判断问题集中在哪一段。这篇文章只讲怎么用这两个工具看懂结果，不涉及任何客户端配置修改。

## ping 和 MTR 分别是什么

- **ping**：最基础的网络诊断命令，往目标地址发送若干个数据包，返回每个包的往返时间（延迟），以及有没有丢失。Windows、macOS、Linux 都自带，不需要额外安装；
- **MTR（Linux/macOS）/ WinMTR（Windows）**：相当于 ping 和 traceroute 的结合体，会持续探测到目标路径上的每一跳（每一个中间节点），并统计每一跳各自的延迟和丢包率，而不只是看最终目标的总体结果。

两者的关系：ping 只告诉你"到目标整体怎么样"，MTR 告诉你"路径上具体哪一跳开始变差"，排查网络路径问题时通常先用 ping 确认有没有问题，再用 MTR 定位问题大致在哪一段。

## 怎么用：ping

1. Windows 打开"命令提示符"，macOS/Linux 打开"终端"；
2. 输入 `ping 目标地址`（比如 `ping 一个你平时访问的网站域名`），Windows 默认只发 4 个包就停止，加上参数 `-t` 可以持续发送（按 Ctrl+C 停止）；
3. 观察返回的每一行：`time=` 后面的数字是本次往返延迟（毫秒），如果出现 `Request timed out` 或统计里的丢包百分比不是 0%，说明这一段路径有丢包；
4. 建议分别测两组：连接机场代理时 ping 目标网站，以及不连代理时 ping 同一个目标，对比延迟和丢包差异，帮助判断问题是不是和代理线路相关。

## 怎么用：MTR / WinMTR

1. macOS：终端输入 `mtr 目标地址`；多数 Linux 发行版需要先安装 `mtr` 或 `mtr-tiny` 包；Windows 没有自带 MTR，需要下载 WinMTR 这个小工具（一个免费的图形化版本）；
2. 运行后会持续刷新，列出从你本机到目标地址之间，途经的每一跳 IP 或域名，以及每一跳各自的延迟、丢包百分比；
3. **建议持续运行 1-2 分钟以上再看结果**：刚打开时数据样本太少，波动大，容易误判；
4. 重点看两类异常：某一跳的丢包率突然从 0% 跳到较高数值，并且往后的所有跳都跟着丢包（通常说明问题出在这一跳附近）；或者某一跳延迟突然大幅上升，之后保持在高位。

## 结果怎么解读：一张对照表

| 现象 | 大致含义 | 下一步 |
| --- | --- | --- |
| 前几跳（本机到路由器、到运营商出口）就开始丢包 | 问题可能在本机网络或本地运营商，与机场代理关系不大 | 检查本机网络、路由器，换一个网络环境再测 |
| 中间某一跳开始丢包，后续跳也跟着丢包 | 问题可能出在这一跳对应的网络设备或链路 | 记录这一跳的 IP，作为反馈服务商的依据 |
| 只有某一跳单独显示高丢包，但后续跳恢复正常 | 这一跳本身可能限制或不响应探测包，是常见的正常现象，不一定代表真实故障 | 重点看后续跳和最终目标的数据，而不是中间这一个孤立的点 |
| 所有跳都正常，只有最后到目标服务器的那一跳变差 | 问题更可能在目标网站服务器一侧 | 换其他网站测试对比，确认不是你这边的线路问题 |

## 使用时需要注意

- **中间某一跳显示高延迟或丢包，不一定代表真正故障**：部分网络设备对探测包的处理优先级较低，会在 MTR 结果里显得"异常"，但实际转发真实流量时不受影响，这是 MTR 使用中常见的误读来源，重点应该看趋势和最终目标的数据，而不是揪着中间某一个跳不放；
- **不同次测试结果会有波动**：和测速一样，MTR 结果也是某个时间段内的采样，建议在怀疑有问题的时间段（比如晚高峰）多测几次，具体怎么理解这种波动可以看[机场测速结果为什么每天不一样](/knowledge/why-speed-test-varies-daily/)；
- **这是定位辅助工具，不是修复工具**：MTR 只能帮你大致判断问题范围，本身不能解决丢包或延迟问题，确认范围后，个人能做的通常是换节点或换线路，更深层的网络问题需要服务商处理。

## 自己验证的建议流程

1. 先用[怎么测速](/tutorials/how-to-test-airport-speed/)里的方法确认确实存在延迟高或丢包的问题，而不是单纯感觉"卡"；
2. 用 ping 对比连代理前后的差异，初步确认问题和代理线路是否相关；
3. 用 MTR 跑 1-2 分钟，记录下丢包或延迟明显上升的那一跳；
4. 换一个节点重复第 3 步，对比两次结果，如果换节点后问题消失，说明是原节点或线路的问题；
5. 如果怀疑是普遍性问题，再把 MTR 的截图或记录提供给服务商客服，方便对方定位，而不是只说"连不上"或"很卡"。延迟和丢包背后的基本概念，可以参考[机场延迟多少算正常](/knowledge/airport-latency-normal-range/)和[机场丢包率多少算高](/knowledge/airport-packet-loss-explained/)。

## 常见问题

**用 MTR 发现中间某一跳一直 100% 丢包，是不是这段路径断了？**
不一定。如果这一跳之后的所有跳以及最终目标都显示正常，很可能只是这台设备不响应探测包，属于常见现象，不代表真实流量也会在这里丢失。

**Windows 要怎么安装 MTR？**
Windows 本身不自带 MTR，通常使用 WinMTR 这个免费的替代工具，界面更简单，功能上和 MTR 类似。

**MTR 显示的丢包率很高，但实际用着没感觉到卡，是怎么回事？**
有可能是上面提到的"中间跳不响应探测包"的情况，真实流量没有受到影响；也可能是丢包确实存在，但你当前使用的场景（比如普通网页浏览）对这种程度的丢包不敏感，具体可以结合[机场丢包率多少算高](/knowledge/airport-packet-loss-explained/)里的参考区间判断。
