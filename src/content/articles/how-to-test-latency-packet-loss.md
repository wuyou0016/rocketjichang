测丢包和测网速用的不是同一类工具。下载速度、上传速度一般用网页测速工具就能看到结果，但丢包率和延迟波动更适合用 ping、MTR、WinMTR 这类路由追踪工具来观察，因为它们能显示数据包经过的每一跳，而不只是一个笼统的总分。这篇文章讲的是具体怎么用这几类工具自测，测速本身的方法可以看[机场测速怎么做](/tutorials/how-to-test-airport-speed/)，测完之后数字怎么解读可以看[机场延迟多少算正常](/knowledge/airport-latency-normal-range/)和[机场丢包率多少算高](/knowledge/airport-packet-loss-explained/)。

## 为什么不能只用测速工具看丢包和延迟

常见的网页测速工具主要给出下载、上传速度和一个综合延迟数字，但它不会告诉你延迟波动是发生在哪一段、丢包具体出现在路径中的哪一跳。如果只看测速结果里的一个延迟数字，遇到延迟偏高或者偶尔卡顿时，很难判断问题出在客户端、本地网络、中转节点还是落地服务器。路由追踪类工具的价值在于，它会把整条路径拆开，逐跳显示延迟和丢包情况，更适合用来定位问题，而不仅仅是给出一个结论性的分数。

## 常用工具一览

| 工具 | 适用系统 | 特点 |
| --- | --- | --- |
| ping | Windows / macOS / Linux 都自带 | 最基础，只测到目标的往返延迟和丢包，不显示中间路径 |
| MTR | macOS / Linux（需安装），部分发行版预装 | 持续发包并显示每一跳的延迟和丢包，结果会随时间刷新 |
| WinMTR | Windows | MTR 的 Windows 图形化版本，用法和功能类似 |
| PingPlotter | Windows / macOS | 图形界面更直观，适合长时间后台监控并画出延迟趋势图 |
| 客户端自带延迟测试 | Clash 系客户端等 | 测的是客户端到节点的连接质量，操作最简单，但看不到中间路径 |

如果只是想快速确认某个节点能不能用，客户端自带的延迟测试已经够用；如果想搞清楚丢包具体出在哪一段，就需要用 MTR 或 WinMTR 这类工具。

## Windows 下用 WinMTR 测试的步骤

1. 下载并打开 WinMTR（它是一个绿色软件，不需要安装）；
2. 在"Host"栏填入要测试的目标地址——测试机场节点时，通常填节点的服务器地址或 IP；
3. 点击"Start"开始测试，让它持续运行一段时间（建议至少几分钟），时间太短容易被偶然的网络抖动影响；
4. 测试过程中可以正常使用网络，不需要停止其他程序；
5. 观察完成后点击"Stop"，结果会显示每一跳的丢包率（Loss%）、平均延迟（Avg）等列。

## macOS / Linux 下用 MTR 测试的步骤

1. 如果系统没有自带，先通过包管理工具安装 MTR（不同发行版的安装命令不同，具体可查阅系统自带的软件源）；
2. 在终端执行 `mtr 目标地址`，默认会进入持续刷新的交互界面；
3. 让它运行一段时间后，按 `q` 退出，观察 Loss% 列和延迟列的变化；
4. 也可以加上参数输出固定次数的报告形式结果，方便截图记录和对比。

## 怎么读测试结果，避免常见误判

- **只看最后一跳（目标本身）的丢包率，不要被中间跳的丢包吓到**：很多网络设备出于安全或负载考虑，会限制自己响应 ICMP（也就是 ping/MTR 使用的协议）的速度，这会让中间某一跳显示"丢包"，但这通常不代表实际数据传输真的丢失，只要最后一跳（真正的目标）丢包率正常，中间跳的高丢包往往可以忽略；
- **多测几次、覆盖不同时段**：和测速一样，单次结果容易受偶然因素影响，建议白天和晚高峰各测一次，具体原因可以看[机场测速结果为什么每天不一样](/knowledge/why-speed-test-varies-daily/)；
- **ping/MTR 测的是 ICMP 流量，不完全等于代理协议的实际表现**：机场代理实际使用的协议（比如基于 TCP 或基于 UDP 的协议）和 ICMP 是不同的传输方式，网络设备对两者的处理策略可能不一样，ping/MTR 显示正常不代表代理连接一定没有问题，反过来也是，这类工具更适合作为辅助排查手段，而不是唯一依据；
- **测的是到节点服务器的路径，不是到最终访问目标的路径**：如果你发现打开某个网站慢，但测节点本身的丢包和延迟都正常，问题也可能出在目标网站自身的响应速度上，而不是机场代理这一段。

## 常见问题

**MTR 和 ping 有什么区别？**
ping 只给出到目标的一个往返延迟和丢包结果，不显示中间经过了哪些节点；MTR 会持续发包并逐跳显示路径上每一段的延迟和丢包，信息更详细，适合定位问题具体出在哪一段。

**为什么 MTR 显示中间某一跳丢包很高，但网络用起来并不卡？**
这种情况比较常见，很多路由设备会限制自己回应 ICMP 请求的优先级，导致它在 MTR 里显示丢包，但这不影响它正常转发你的真实流量。判断是否真的有问题，应该优先看最后一跳（也就是目标本身）的丢包率。

**测节点的 IP 和测实际网站的地址，结果会不一样吗？**
会。测节点 IP 反映的是你到这个机场节点服务器之间的路径质量；测具体网站地址，走的路径可能包含节点之后到目标网站的一段，两段路径的质量不完全一样，如果只是想确认节点本身状况，建议直接测节点地址。

**手机上可以用类似的工具吗？**
应用商店里有一些提供 ping/路由追踪功能的手机 App，原理和电脑端类似，但手机网络环境（尤其是移动网络）本身波动更大，测试结果的参考价值通常不如电脑端稳定的网络环境。

**一定要用专业工具才能判断网络好不好吗？**
不一定。如果只是日常使用，感受到的卡顿、加载慢本身就是最直接的信号；MTR、WinMTR 这类工具更适合在怀疑是网络路径问题、需要进一步定位原因时使用，而不是每次都要测一遍。
