如果订阅里的 VLESS、Trojan 节点能正常连接，但 [Hysteria2](/knowledge/what-is-hysteria2-protocol/) 或 [TUIC](/knowledge/what-is-tuic-protocol/) 这类基于 UDP 的节点连不上、连上又频繁掉线，问题大概率和 UDP 流量本身在你所在网络环境中的表现有关，而不一定是节点或账号出了问题。通用的连接排查思路可以先看 [机场连接不上怎么办](/troubleshooting/connection-troubleshooting-step-by-step/)，这篇文章专门针对 UDP/QUIC 类协议的特殊情况展开。

## 直接结论

先做一个简单判断：把客户端切换到同一订阅里的 VLESS、Trojan 或其他基于 TCP 的节点，如果能正常连接，基本可以确定问题出在 UDP 流量本身，而不是账号或订阅失效；如果切换协议后同样连不上，说明问题更可能出在订阅、账号或本地客户端配置上，应该按通用排查思路处理。

## 为什么 UDP/QUIC 类协议容易出现这类问题

Hysteria2、TUIC 都基于 QUIC 传输层，用 [UDP 转发](/glossary/udp-forwarding/) 承载数据，这和大多数运营商网络里"以 TCP 为主"的流量特征不同，可能遇到几类特有的情况：

- **运营商或本地网络限制 UDP**：部分家庭宽带、公共 Wi-Fi、企业网络会对 UDP 流量做限速或直接拦截，尤其是非常见端口上的 UDP 流量，更容易被识别和限制；
- **QUIC 流量被单独识别处理**：QUIC 是一种相对新的传输协议，部分网络设备对其识别和处理机制还不完善，可能出现和 TCP 流量不一致的表现；
- **MTU 分片问题**：QUIC 对 [MTU](/glossary/mtu/) 比较敏感，如果链路中某一段的 MTU 设置和数据包大小不匹配，可能导致分片失败，表现为连接不稳定或频繁重连；
- **本地防火墙/安全软件拦截**：部分杀毒软件、防火墙规则默认只放行常见的 TCP 端口，可能直接拦截客户端使用的 UDP 端口。

## 排查步骤

按下面顺序逐步排查，通常能比较快定位问题：

1. **对照测试协议**：如前面所说，先用同一订阅里的 TCP 类协议（VLESS、Trojan）测试是否能连接，缩小问题范围；
2. **检查本地防火墙和安全软件**：临时关闭系统防火墙或第三方安全软件（测试后记得重新开启），确认是否是本地拦截导致；
3. **检查客户端的协议相关设置**：确认客户端里 Hysteria2/TUIC 节点的端口、混淆、带宽参数等配置和订阅提供的信息完全一致，一个字符的差异都可能导致连接失败；
4. **更换网络环境测试**：尝试切换到手机热点或另一个网络环境，如果换网络后能正常连接，说明问题出在原网络对 UDP/QUIC 的限制上；
5. **调整 MTU 相关参数**：部分客户端支持手动设置 MTU 大小，如果怀疑是分片问题，可以尝试调低 MTU 数值后重新测试；
6. **观察是否只是速度异常而非完全连不上**：如果能连接但速度明显低于预期，问题可能出在 UDP 限速而非完全拦截，这种情况下更换协议通常是更直接的解决办法，而不是继续排查网络配置。

## 什么情况下应该直接换回 TCP 类协议

如果排查后确认是本地网络环境对 UDP/QUIC 流量有明显限制，而你又没有条件更换网络（比如公司网络、公共 Wi-Fi），更现实的做法是直接使用 VLESS、Trojan 等基于 TCP 的节点，而不是持续尝试各种参数调整。协议是否"新"或者"设计上更高效"，在网络环境本身不支持的情况下都无法体现出优势，这一点在 [TUIC 是什么协议](/knowledge/what-is-tuic-protocol/) 里也提到过。

## 什么情况需要联系服务商

如果确认本地网络对 UDP 没有限制（比如换过网络、关闭过防火墙都无法解决），并且同一账号下的 TCP 协议节点也存在类似的连接问题，这时候更可能是节点或账号层面的问题，可以联系服务商客服，提供具体的错误提示、测试时间和已经尝试过的排查步骤，方便对方定位。

## 怎么确认问题已经解决

调整完设置或更换网络之后，不要只看客户端界面显示"已连接"就认为问题彻底解决，最好再持续观察一段时间。可以用 Ping 或 MTR 做几轮测试，确认延迟和丢包是否稳定，具体操作方法可以看 [怎么用 Ping 和 MTR 自测机场延迟和丢包](/tutorials/how-to-self-test-latency-packet-loss-with-ping-mtr/)。如果只是偶尔重连一次就恢复正常，也可能只是网络本身的瞬时波动，不一定意味着彻底解决了根本原因，后续如果重复出现同样的情况，还是建议按前面的步骤重新排查一遍。

使用任何网络代理服务时，请遵守你所在地区的法律法规。

## 常见问题

**为什么 Hysteria2 节点昨天还能用，今天突然连不上？**
可能是所在网络环境的运营商策略发生了变化，也可能是本地网络本身波动，建议先按上面的排查步骤逐一确认，尤其是先做协议对照测试。

**换成手机热点后 UDP 节点就能连上，说明什么？**
基本可以确定原来的网络环境对 UDP 流量存在限制或干扰，这种情况下，在原网络下更适合使用基于 TCP 的协议节点。

**调整 MTU 之后还是不稳定怎么办？**
如果调整 MTU 没有明显改善，说明问题可能不是分片导致的，建议回到前面的排查顺序，重点检查本地防火墙设置和网络本身对 UDP 的限制情况。

**是不是所有 UDP 连接问题都要归咎于网络环境？**
不一定，也有可能是客户端配置错误或节点本身临时故障，这也是为什么第一步要做协议对照测试——如果 TCP 协议节点同样无法连接，问题更可能出在订阅或账号层面。
