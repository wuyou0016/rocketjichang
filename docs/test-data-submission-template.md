# 真实测试数据提交模板

用途：解决"最稳定的机场"榜单长期为空的问题。榜单要求每个服务商至少 2 条、时间跨度 7 天以上的**本站真实测试记录**才会出现排名——不能用官方宣传或第三方数据代替。这个模板是为了让你（或任何实际操作测速工具的人）每次测完后，把结果按这个格式发给 Claude，就能几分钟内录入网站，不需要每次都重新解释一遍数据结构。

已知你之前用 **MiaoKo 自定义测速工具**做过一次无忧链接的实测（2026-07-18），如果继续用同一个工具，只要按下面格式把结果发过来即可。用别的工具/别的指标也可以，只要是你自己真实操作、真实观测到的数据。

## 最低有效字段（照抄这几行即可）

```
服务商：<无忧链接 / 微风网络 / Firefly / 灵猫网络 / 闪跃 / 跨界云>
测试日期：<YYYY-MM-DD>
测试工具/方法：<比如 MiaoKo 4.7.0，或者其他>
测试环境：<比如 珠海联通 9Gbps 出口>
丢包率（packetLossPercent，百分比数字，最有价值）：<有就填，没有就写"无">
延迟（latencyMs，可选）：<...>
下载速度（downloadMbps，可选）：<...>
其他备注：<比如某个节点异常、工具本身的免责声明等，如实写，不用美化>
```

## 规则（不能违反）

- **只填你真实观测到的数字**，没测的字段留空或写"无"，不要为了填满字段编数字。
- 丢包率（packetLossPercent）是最优先的字段——这是原始观测值，直接用于稳定性评分；如果没有丢包率，会退回用"稳定性评分"这种加工指标（如果你的工具能给出的话），但网站会明确标注这是加工指标，不会混着说。
- 一条记录不够，至少要**同一个服务商积累 2 条、时间跨度 7 天以上**才会真正出现在榜单里（`MIN_STABILITY_TEST_RECORDS=2`，`MIN_STABILITY_SPAN_DAYS=7`，定义在 `src/data/utils/ranking-constants.ts`）。
- 数据一旦提交并写入 `src/data/tests/tests.json`，不会被我事后调整或"优化"成更好看的数字。

## 现状（2026-09-01 当前，逐服务商）

| 服务商 | 现有本站测试记录数 | 还差什么 |
|---|---|---|
| 无忧链接 | 1 条（2026-07-18，仅覆盖测速与解锁，不含丢包率/稳定性评分） | 需要 1 条**含丢包率或稳定性评分**、且日期与 07-18 相隔 ≥7 天的新记录 |
| 微风网络 / Firefly / 灵猫网络 / 闪跃 / 跨界云 | 0 条 | 需要 2 条含丢包率或稳定性评分的记录，时间跨度 ≥7 天 |

（这份现状表与 [/rankings/most-stable/](https://rocketjichang.com/rankings/most-stable/) 页面上公开展示的表格数据一致，来自同一份真实数据，不是两套口径。）

## 之后怎么用

测完之后，把上面的模板填好发给我，我会：
1. 按 `src/content.config.ts` 里 `tests` 集合的 Schema 写入 `src/data/tests/tests.json`；
2. build 验证 → 部署 → 生产环境核实；
3. 如果某个服务商因此达标，"最稳定的机场"榜单会自动把它排进去，不需要额外操作。
